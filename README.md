# DVTapeMerger

同じ miniDV テープを複数回キャプチャしたファイル（WinDV の `.avi`、iMovie の `.dv` / `.mov` など。撮影カットごとに分割されたもの、1 本にまとめたもの、細切れになったもののどれでも可）から、
フレーム単位・ブロック単位で良好なデータを選び、**1本の動画ファイル**にまとめる Windows 用ツールです。

[dvrescue](https://github.com/mipops/dvrescue) の「複数キャプチャから良い部分を選ぶ」という考え方をもとに、
タイムコードが壊れたキャプチャでも正しく結合できる結合処理を内蔵しています（設定で dvrescue を使うこともできます）。

## 主な機能

- キャプチャファイル（`.dv` / `.dif` / `.avi` / `.mov`）をフォルダーごと追加
- 各ファイルの DV ストリームからタイムコード・撮影日時・ブロックエラーを読み取り
- タイムコードと撮影日時の範囲が重なるファイルを自動で「グループ」にまとめる
  （キャプチャごとに分割位置が違っていても、同じ区間を含むファイル同士が組み合わされます）
- グループごとに、同じフレームの映像・音声ブロックのうち壊れていないものを採用（サブコードのタイムコード・撮影日時も修復）
- 結果を撮影順に連結して 1 本で出力（`.dv` / `.avi` (Type-2) / `.mov` / `.mkv`）
- 入力ごと・結合後の映像エラー・音声エラー・タイムコードの状態をグラフ表示（表示項目は切り替え可能）、レポート（`report.txt`）とシーン一覧（`scenes.csv`）を保存

## メタ情報について

DV では撮影日時・タイムコード・カメラ情報などは各フレームの DIF データ内に記録されています。
本ツールはどの出力形式でも DIF フレームを一切再エンコード・改変しないため、これらの情報はそのまま残ります
（`.mov` / `.mkv` / `.avi` から取り出した映像データが `.dv` 出力とバイト単位で一致することを確認済み）。

加えて、コンテナ形式では次の情報を付けます。

| 出力形式 | 作成日時 (creation_time) | 開始タイムコード | チャプター（撮影開始ごと） |
| --- | --- | --- | --- |
| `.dv`  | （DIF内のみ） | （DIF内のみ） | — （`scenes.csv` に出力） |
| `.mov` | ○ | ○ (tmcd) | ○ |
| `.mkv` | ○ | ○ (タグ) | ○ |
| `.avi` | — | — | — |

## ダウンロード

[Releases](../../releases) から次のどちらかをダウンロードして展開してください（インストールは不要です）。

- `DVTapeMerger-<版>-win-x64.zip`: 単体で動く版（約 50 MB）
- `DVTapeMerger-<版>-win-x64-fdd.zip`: 小さい版（要 [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0)）

## 必要なもの

- Windows 10 / 11（x64）
- 小さい版を使う場合は [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0)（ビルドする場合は .NET 10 SDK）
- **FFmpeg**: AVI・MOV ファイルの読み込みと、`.dv` 以外での出力に必要（`ffmpeg.exe` に PATH が通っていれば自動検出）
- （任意）**dvrescue CLI**: 設定で結合処理に dvrescue を使う場合のみ。<https://mediaarea.net/DVRescue>

FFmpeg と dvrescue は本リポジトリには含まれていません。[ツール] → [設定] で場所を指定するか、
`DVTapeMerger.exe` と同じフォルダーに置いてください。

## ビルド

```
cd src
rem 小さい版（.NET 10 Desktop Runtime が必要）
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o ..\publish\fdd
rem 単体で動く版
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o ..\publish\win-x64
```

アイコン（`src/app.ico`）は `assets/make-icon.ps1` で生成しています。

## 使い方

1. [フォルダーを追加...] で、同じテープのキャプチャファイルをすべて追加します（複数回分のキャプチャを混ぜて追加して構いません）。
2. [解析] を押すと、各ファイルのフレーム数・タイムコード・エラー率が表示され、結合グループが作られます。
   グループを選ぶと、入力ごと・結合後のエラー分布がグラフで表示されます。
3. 出力ファイルと形式を選び、[結合を実行] を押します。

コマンドラインでも実行できます。

```
DVTapeMerger.exe --cli [--ffmpeg path] [--work dir] [--no-logs] [--analyze] [--engine builtin|dvrescue] [--dvrescue path] -o output.mkv 入力フォルダーまたはファイル...
```

## 処理の流れと注意点

- **AVI / MOV**: FFmpeg のストリームコピーで DV ストリームを取り出してから使います（無劣化。取り出したデータは作業フォルダーの
  `cache` にキャッシュされ、終了時に削除されます）。作業フォルダーには、AVI・MOV の合計サイズと同程度の空き容量が必要です。
  映像が DV 形式のもの（DV のまま保存されたもの）だけが使えます。H.264 などに変換されたファイルは読み込めません。
  音声は DV ストリーム内の音声を使うため、AVI・MOV 側の音声トラックの数や内容は関係ありません。
- **タイムコードの補正**: 古いテープでは、映像は無事でもサブコード（タイムコード）だけが読めない・前のフレームの値のまま、
  といったことがキャプチャごとに起こります。「タイムコード − ファイル内の位置」は連続した区間では一定なので、
  前後約15フレームの読み取り結果の多数決（読み取れたパック数で重み付け）で各フレームのタイムコードを決め直します。
- **グループ分け**: タイムコードが逆戻りする箇所や大きく飛ぶ箇所ではファイル内でも区間を分け、
  タイムコード範囲と撮影日時範囲がともに重なる区間同士を同じグループにします。グループは撮影日時順に連結されます。
- **結合**: 同じタイムコードの候補フレーム同士で、壊れていないブロックの中身が一致することを確認してから
  （一致しない候補は別のフレームとみなして使いません）、エラーの少ないフレームを基準に、壊れたブロックを他のキャプチャの
  同じ位置のブロックで置き換えます。前後のフレームのデータが混ざることはありません。
  サブコードは、そのタイムコードを正しく読めたキャプチャのものを使い、どのキャプチャでも読めない場合は補正後のタイムコードを書き込みます。
- どのキャプチャでもほぼ全ブロックが壊れていて、タイムコードも読めないフレーム（録画終了後のノイズなど）は出力しません。
- **dvrescue を使う場合の注意**: dvrescue はタイムコードだけでフレームを対応付けるため、タイムコードが壊れたキャプチャが
  含まれると、前後のフレームが混ざったり同じフレームが重複したりすることがあります（再生時のチラつきの原因になります）。
- タイムコードが記録されていない区間は、他のキャプチャと対応付けできないため単独で出力されます。
- どのキャプチャでも同じ場所が壊れている場合は修復できません（結合は「良い方を選ぶ」処理です）。
- 途中で音声の形式（32kHz/12bit ↔ 48kHz/16bit など）が変わるテープは、`.dv` 形式での出力をお勧めします
  （`.mov` / `.mkv` / `.avi` では音声が正しく出力されない場合があるため、結合前に確認します）。
- NTSC と PAL のファイルを混ぜて結合することはできません。
- フォルダーごと追加すると、前回の結合結果（`merged.mov` など）も入力として読み込まれます。不要な場合は一覧から削除してください
  （出力ファイルと同じファイルを入力にすることはできません）。
- 映像エラーは、映像 DIF ブロックのうち STA（エラー状態）が 0 以外のもの（またはブロック ID が壊れたもの）です。
- 音声エラーは、音声 DIF ブロックのうち、実際にサンプルが入る位置（DV 規格の音声配置に従って算出）にエラーコード
  （12bit: 0x800、16bit: 0x8000）があるものです。1フレーム中の空き位置や、録音されていないチャンネル
  （12bit 4ch 記録で使われていない 3/4ch）は数えません。
